# PitchTrace Edge 需求、模块与开发计划

在首场四路试点中，复核员应能找回一次真实传球，跟随传球者与接球者的轨迹，在三维画面里查看球与脚的运动，再调出同一曝光时刻的各机位原片。Edge 交付场景快照、原片及其逐帧时间索引。Live 接收这些产物，负责分发、显示和人工复核。

软件开发与现场取证可以分别进行。Edge 已提供整场离线处理、按封口媒体段持续处理和配套评估工具。生成样例与文件源用于回归，现场对时、独立米制精度、动作质量和四路长时吞吐分别在 G1–G6 测量。首期配置为四个支架 A–D，每架一台单摄。[运行完整流程](../edge/README.md#不接相机跑完一场样例) · [总体排期与 G1–G7](03-development-plan.md)

## 一、已有能力和开发起点

整场运行可用 `run-match`。场景库保存配置、标定来源、软件与模型版本、逐帧证据和网关回执。连续采集时 `stream-match` 在各路原片封口并取得逐帧曝光后处理，录像、推理和上行可分别推进。下面的基准是录像准备与审计阶段的测量。[运行与恢复](../edge/docs/run-match.md) · [连续处理](../edge/docs/stream-match.md)

| 已可使用 | 已验证的行为 | 下一步 |
| --- | --- | --- |
| 2–8 机位录像重放 `replay` | 双路跨周期回归覆盖 220 帧。四路 320×180 样例各重放 30 分钟，A 在第 15 分钟重置，逐帧核对全部 198,000 帧与跨周期顺序，缺口为零。[实测耗时、帧率与峰值内存](../edge/benchmarks/2026-11-26-four-camera-30min.json) | 取得真机重连时的曝光映射，在目标分辨率下验证四路现场采集、对时和长时资源开销。 |
| 2–8 机位闪光报告 `audit-sync` | 完整组统计最早至最晚曝光的跨度、P95 和最大值，缺路单列。保留双路有符号偏差。样例回归覆盖完整和缺测标注。 | G1 由场务核对时钟来源、实拍帧和未配对事件。G2 对四台相机拍下的共同闪光复测。 |
| 分区双视角可见率 `audit-visibility` | 按人工标注和逐帧曝光 UTC，分别统计各区地滚球、高球和脚踝的双视角可见次数与计划样本数。生成样例的 4 个样本中有 1 个满足双视角条件。[标注格式与预期结果](../edge/README.md#g1-分区双视角可见率) | G1 由场务与标注人员约定区域、目标、取样时刻和曝光容差，提交实拍分区结果与可追溯的原帧。 |
| 离线镜头与场地标定 `calibrate-intrinsics`、`calibrate` | 从单机位的棋盘格照片拟合内参与畸变，外参标定可按机位、版本和原图尺寸读取报告。双路场地合成样例可重建两个独立地面点和一个高点，单视角高点保留缺测。[输入和报告](../edge/README.md#离线几何标定) | G1 用实拍镜头和独立场地检查点复验。用机位巡检和按曝光切换标定记录复核移机前后的误差。 |
| 单视角人球检测与四路推理 | YOLO11n 人框用于姿态与号码。无近期球心时可用原图裁片和跨曝光运动确认找球。离线与连续处理支持按机位并行、按曝光组融合，归档模型和精搜依据。[启用模型与复核证据](../edge/docs/vision-detection-models.md) · [ISSIA 同片召回、阶段计时与四路积压](../edge/benchmarks/2026-11-27-issia-coldsearch.md) | G3 在另一场实拍中复验近、远端召回率与误检，G5 在目标 Mac 上测量整场吞吐。 |
| 本地原片提交 `publish-media` | Edge 按机位和媒体周期分别提交初始化文件、片段和曝光索引。两个周期可复用同一片段号和 PTS，按曝光 UTC 分别定位并读取原片。 | 在目标网络上测试场景优先、限速补传与原片可用时间。 |

现有实现可从 [CLI 入口](../edge/Sources/PitchTraceEdge/PitchTraceEdge.swift)、[录像导出](../edge/Sources/PitchTraceEdge/RecordingExport.swift)、[曝光审计](../edge/Sources/PitchTraceEdge/ExposureAudit.swift) 和[本地联调步骤](../edge/README.md#用生成样例联调)核对。

## 二、需求与验收口径

R01–R11 属首场 P0，R12 属赛后 P1。**300 秒是现场曝光到浏览器首次绘制的上限**。下表精度、覆盖率、发布频率及按时时隙比例沿用首轮建议值，G1 根据场地、人数、光照和样本冻结口径。实拍试点人数与公网带宽测试的标准负载分别记录。[需求与验收口径](01-requirements.md) · [公网性能要求](04-performance-requirements.md)

| 需求 | Edge 交付与验收方法 | 放行阶段 |
| --- | --- | --- |
| R01、R02　建赛配置、采集、对时 | 绑定比赛 ID，记录场地、机位、序号、位姿、标定版本和曝光时钟。现场与录像输入都保留帧号（设备提供时）、PTS、曝光 UTC、丢帧和缺流原因。四路连续录像 30 分钟，曝光偏差 P95 ≤5 ms，另报最大值。拔一路后其余路继续，恢复的机位重新对时。 | G1 试拍，G2 四路 |
| R03　标定与覆盖 | 输出内外参、版本、分区覆盖图。用未参与拟合的地面点验收 P95 ≤0.30 m，另报已知高度标杆误差。支架移动时隔离该视角，复标后恢复。 | G1 勘查，G2 验证 |
| R04　人员与足球 | 输出稳定轨迹 ID、足底位置和球心位置，保留来源、质量以及实测、预测、丢失状态。球员覆盖率 ≥95%、位置误差 P95 ≤0.75 m。可见球覆盖率 ≥85%、有独立三维参考的球心误差 P95 ≤1.0 m。每 10 球员分钟身份切换 ≤1 次。地滚球、高球分别统计。 | G3，G6 独立复验 |
| R05　球队、球衣号与名单 | 对双人确认可读的轨迹段，自动确认号码正确率 ≥95%、覆盖率 ≥70%，另报全部轨迹段覆盖率和误绑数。覆盖同号跨队、换人、未知和人工更正。性别只关联报名授权字段，可缺省、纠错和隐藏。模型外形单独选择。 | G4、G6 |
| R06、R07　姿态与动作 | 重建可见主要关节并映射为局部旋转。有独立三维参考的可见关节平均误差 ≤0.20 m，另测可见关节输出覆盖率，建议 ≥80%。传球、踢球／射门、带球、过人、铲球逐类报精确率、召回率和样本数，宏平均 F1 ≥0.75。Live 用至少两种外形核对摆腿与缺测表现，复核员记录接触先后或证据不足。 | G4、G6 |
| R08、R09　观赛输入与连续性 | Edge 提供统一时钟、序号、降级状态及分环节计时，Live 负责观赛控制和首次绘制测时。目标配置连续 90 分钟，以 10 Hz 为发布基线，建议 ≥99% 预期时隙在曝光后 300 秒内首次绘制。缺帧和迟到都计入失败，另报已绘制帧延迟 P50、P95 和最大值。 | G5 预演，G6 现场 |
| R10、R11　原片、恢复与场务 | 现场可预览各路、启动或结束采集，查看通道状态与剩余录制时长，按授权留存、清理并记录结果。断网继续录制，重启保留已提交段和待办。与 Live 抽查 20 个事件，按比赛时刻切换证据机位，原片定位误差 ≤1 个采集帧。分角色验证设备写入、原片读取和修订权限。 | G2 基础，G5–G6 联验 |
| R12　归档复算与导出 | 对同一录像按指定标定、模型和配置重放，输出可比较的轨迹与事件索引。按轨迹 ID、时间窗、版本逐项对照，保留 Live 的人工修订历史。 | G7 |

## 三、模块划分与交接

下表按输入与输出分工，初期沿用现有 SwiftPM 程序。A 负责设备与运行，B 负责视觉与几何，C 负责 Live 对接与验收工具。表内列出各模块职责及目标技术；当前可运行的入口和依赖见 [Edge 使用说明](../edge/README.md)。

| 模块 | 输入 → 输出 | 负责人和实现重点 |
| --- | --- | --- |
| 1. 比赛配置与运行管理 | Live 分配的比赛 ID、场地、名单版本、设备配置 → 本场清单、开停状态、通道预览和健康记录 | A。记录版本与留存期，监测帧率、磁盘余量、最老任务年龄和失败时隙。采集、写盘、推理、上行独立排队并设置上限。 |
| 2. 输入与曝光对时 | 相机帧或录像帧、设备时钟 → 带机位、原始帧号、PTS/时基、曝光 UTC 的帧与同步状态 | A。现场按样机选 SDK、AVFoundation 或 RTSP。用共触发或 PTP 配合定时曝光核验。曝光来源不可核验的路保留原片，并排除出精确三维融合。窗口截止时交付已对齐的有效视角。 |
| 3. 分段录像、索引与重放 | 通道帧与曝光映射 → 初始化文件、关键帧起始的媒体段、逐帧索引、缺口和重放输入 | A。沿用现有时序校验，以采集帧率写盘，分段校验后原子提交、更新 Edge 本地索引。四路重放按曝光顺序逐段归并，保留双路确定性。 |
| 4. 标定与覆盖 | 标定板、实测场地点／高点、同步样片 → 带版本的内外参、覆盖图、独立误差 | B。用 OpenCV `calib3d` 经窄 C 接口接入 Swift。输出有效机位与版本给融合模块，更换焦距、分辨率或位姿后复验。 |
| 5. 单视角观测 | 已对齐的机位帧 → 人框、球候选与原图裁片、局部轨迹及观测质量 | B。Core ML 轻量检测从每路 10 Hz 起测，每个入选帧解码和全图检测一次。人员关联、姿态、读号和小球精搜共享结果，记录权重、许可及预处理版本。 |
| 6. 人员关联与球轨迹 | 同期二维观测、标定 → 全场人员轨迹、足底位置、球心及证据机位 | B。用时间、极线和场地位置筛选关联，检查三角化夹角及重投影残差。单视角清晰足点可投影至地面。单视角高球保留二维证据，短时预测到期转缺测。 |
| 7. 球队、号码与身份 | 局部人框、全场轨迹、授权名单 → 带时间范围的球队／号码候选和名单关联 | B。清晰裁片做 OCR、多帧投票，同队有唯一匹配或人工确认后绑定。轨迹 ID、名单 ID、号码分别保存，修号沿用原轨迹 ID。 |
| 8. 姿态与骨骼 | 分机位人体裁片、可见关节、全场轨迹 → 三维关节、缺测记录和绑定骨架局部旋转 | B。Vision 估计二维关节，按同一轨迹与曝光窗口融合，保存原始测量与平滑结果。和 C 对照前端 13 关节，检查左右脚、颈肩和缺测关节。 |
| 9. 动作候选与证据 | 人球轨迹、脚部姿态及连续原片 → 五类候选的时间窗、参与者、置信度及证据帧引用 | B。射门先将摆腿归到具体轨迹，再核对离脚时球速、出球位置和方向。只支持踢球时记录踢球，关键帧遮挡时保留未决。人工判定与修订由 Live 保存。 |
| 10. 场景发布、归档与补传 | 场景、媒体三件与比赛清单 → 本地持久化结果、上传待办、提交回执与缺口 | A、C。Edge 用独立 SQLite 和文件存储，写盘后经 HTTP 接口交付。重连先送当前完整快照，再用余量补历史。恢复扫描孤立段和缺索引，保留确已提交的序号。 |

**共同数据约定。** 场地原点为中圈地面，X 沿长边、Z 沿短边、Y 向上，单位米。球用球心、人员用足底，骨骼采用父骨骼局部四元数 `[x,y,z,w]`。空场、未知号码、失球和缺关节均使用 v2 可表达的缺测状态。逐关节质量和事件证据保存在本地测量记录。对外新增字段或事件修订语义由 A、C 共同评审并补共享样例，破坏性变更另开版本。[场景 Schema](../schemas/v2/scene-frame.schema.json) · [技术设计](02-technical-design.md#edge-live-contract)

**两类交付独立重试。** 场景经 `POST /v2/matches/{matchId}/frames` 写入，以 `(matchId, streamEpoch, seq)` 去重。各通道使用自己的 `mediaEpoch`，媒体时钟重置时切换周期。初始化文件、片段和曝光索引经 PUT 上传，三件校验匹配后供 Live 定位。两类产物按比赛 ID 和曝光 UTC 对齐。同键同内容重试确认，409 冲突保留原提交、记录并告警，422 回溯生产端数据。[媒体索引 Schema](../schemas/v2/media-index.schema.json) · [本地网关接口](../live/server/README.md)

## 四、按周开发与放行

沿用总体计划的 **12 个开发周，另留 2–4 周现场迭代**。W1 从获得可进场时段和样机起算。估算按 A、B、C 三人全职计算，C 同时负责 Live。场务、两名独立标注员和复核员按场次参与。第 2 周用现场画质、对时和目标机初测结果复估模型工作量与排期。

| 周次 | 负责人、依赖与开发任务 | 当周可检查的交付物与放行决定 |
| --- | --- | --- |
| W1 | A、场务落实授权与留存，勘测 A–D，只在两个支架先装机。B 布设拟合点和独立检查点。C 用现有样例复跑原片归档与换机位。 | 提交两路可解码实拍、曝光来源和共同闪光标注，附场地图、采样清单及软件基线。具体取证顺序见第五节。 |
| W2 | A 做对时审计与目标机解码／模型初测。B 核对远端球、号码、地滚／高球和脚踝的分区双视角可见率，试算独立地面与高点误差。 | **G1** 提交同一脚传球的双路原帧、对时／覆盖／几何报告，冻结区域、人数、照明、样本分母和四路配置。不足则先改位、调焦或换触发方式，复拍同一区域再评审。 |
| W3 | G1 后，A 接入选定接口，将现场与录像归一为同一种带曝光信息的帧。先跑通一台的录像、重连和周期切换，再扩四路。B 生成首版标定，C 准备时钟重置与缺件回归。 | 每路能预览、分段录制并从原片定位到曝光帧。回放与现场采用同一坐标、机位标识和时钟映射。 |
| W4 | A 完成有界四路回放和通道隔离，B 完成覆盖图、移动检测和复标。A、C 核对媒体三件重传。 | **G2** 四路连续录制 30 分钟。建议逐次共同闪光列出四路曝光，按完整组的最早至最晚曝光差计算 P95、最大值，单列缺机位的事件，统计口径在 G1 冻结。复测独立检查点、拔线和移机，留存告警、其余路连续性及新标定生效时刻。 |
| W5 | G2 后，B 先打通同一脚实拍地面传球的检测、足点投影、跨机位 ID 和球心。A 提供原图裁片及分段性能记录。C 对照 v2 正反例。 | 第一份来自实拍的场景帧，每个测量可追到来源机位、曝光及标定版本。以空场、丢球、未知号码、交叉跑位检查行为。 |
| W6 | B 加入高球、小球精搜、遮挡恢复和预测时限。A 实现最小发布器，向本地网关提交实拍快照与媒体三件。C 在浏览器核对暂停时刻。 | **G3** 浏览器可找回同一脚地面传球及一次高球的三维轨迹和同步原片。交付近／远端覆盖、米制误差、ID 切换与失败片段。 |
| W7 | 以 G3 稳定轨迹为输入，B 实现清晰背号多帧投票及二维关节融合。A 为全员基础姿态保留算力，优先提高持球人的姿态更新频率。A、C 对齐候选事件标识、证据帧引用和人工修订样例。 | 同号跨队、遮挡和换人的固定片段能重放。用两种模型外形检查局部骨骼，修号前后可由同一轨迹 ID 对照。 |
| W8 | B 以轨迹、摆腿和球运动生成五类候选。A 关联原片时窗，C、复核员完成查找、切视角与修订。 | **G4** 独立复核员能找到事件并检查触球／接触顺序。交付读号、关节覆盖与误差、逐类动作指标及证据不足样本。 |
| W9 | G3、G4 后，A 实现持久化待办、当前帧优先、限速补传和重启恢复。B 按队列年龄调度推理。C 接通绘制计时与权限验证。 | 在断路、断网、网关重启、磁盘不足时均有可追踪记录。恢复后旧帧入档，直播游标继续前进。重复提交不会产生第二份记录。 |
| W10 | A、B 在目标机以原速重放四路、目标人数 90 分钟，逐项开启检测、姿态和 OCR。C 按原始曝光间隔排定本次重放时隙，测从预定时隙到浏览器首次绘制的耗时。 | **G5** 交付正常及降级时段的重放延迟、队列年龄、缺帧、峰值内存、磁盘、热机吞吐和每场耗电，完成故障预演。持续积压时先调 OCR、远离球的姿态，再调次要视角。保存原片，复跑同一输入。 |
| W11 | G5 后，A、B、C 与场务组织独立比赛，校准时钟，用同屏拍摄或可追溯时间码独立复核延迟。 | **G6** 逐项签收 R01–R11，抽查 20 个事件的原片定位，分别记录通过、未通过、样本不足。修复项用另一段实拍复验。 |
| W12 | 依据 G6 结果，A 打包程序、设备配置与恢复手册，B 归档模型／标定并复算，C 对照检索、导出及人工修订。 | **G7** 同一比赛两次计算结果可按轨迹、事件和版本比较。发布说明列出实测机型、场地、人数、照明及遗留项。P0 问题关闭或由项目方明确缩小试点范围。 |

**公网性能单列验收。** W5 起 C 可用固定输入评估编码，W9–10 与 A 做上行限速和恢复测试。纯三维使用 22 人 × 13 关节、10 Hz 的持续运动样本，Edge 出口限速 1 Mbps，统计包含封装和重试的实际流量。建议 10 秒滑动窗口均值 ≤0.8 Mbps、1 秒窗口 P99 ≤1 Mbps。另测量化附加位置／旋转误差及恢复后首次绘制当前帧用时。原片另计带宽，本地 G3 实拍联调可独立推进。公网达标还需 Live 完成独立下载限速及双端同时限速的测试。[限速与恢复测试](04-performance-requirements.md#7-限速断网与恢复测试)

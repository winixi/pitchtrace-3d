# 场迹 · 落地开发计划

**目标**　在一块约定尺寸的真实足球场，用四组双目摄像头和一台指定配置的 Mac mini 完成一场试点比赛。观众能在约 30 秒内看到三维画面，复核员能从一次传球或铲球跳回同步原片。交付依据是[详细需求说明](01-requirements.md)的 R01–R12，模块和接口见[技术实现方案](02-technical-design.md)。

## 1. 排期假设与关键路径

**建议排期为 12 个开发周，另留 2–4 周现场迭代余量。** 估算假定三名全职工程师、一处能重复进场的场地、两次完整外场测试，以及可用于开发与评测的授权录像。相机交期和场地档期可能延长日历时间。第 2 周依据远场像素、双目同步和 Mac mini 基准调整范围与日期。

| 角色 | 主要责任 | 试点投入假设 |
| --- | --- | --- |
| A · 边缘与设备工程师 | 场勘、设备接入、对时、录制、性能和故障恢复 | 1 人全职 |
| B · 视觉与几何工程师 | 标定、轨迹融合、球、骨骼、读号、动作评估 | 1 人全职，复杂模型或标注量在第 2 周复估 |
| C · 全栈与交付工程师 | 数据契约、档案、网关、观看与复核、验收脚本和发布 | 1 人全职 |
| 场务、教练／裁判、测试与标注人员 | 进场安装、组织脚本动作、提供独立标注、复核争议样本 | 按场次排班，两人独立标注，分歧由第三人裁定 |

关键路径依次为**拍清并对齐八路画面 → 建立共同坐标 → 跨机位稳定追踪人球 → 重建姿态与事件 → 90 分钟端到端实测**。网关、观看端、归档和标注工具可用录制数据并行开发。现场首个成果是用两处支架拍一段真实传球，在浏览器显示轨迹并跳回同一脚触球的原片。

## 2. 设备、数据与场地准备

| 准备项 | 数量或记录内容 | 开工前取得的证据 |
| --- | --- | --- |
| 双目设备、安装与供电 | 4 组、8 光路；支架、线缆、必要的防雨和稳固措施 | 接口、macOS SDK、曝光时间戳、触发、实际帧率、镜头覆盖范围；每路一段可解码样片。 |
| 网络与时钟 | 按码率选交换机、上联和网口；共触发线或支持所选对时方式的相机、网络和时间源 | 实测同时传输时的丢帧和曝光偏差，保存布线图与端口表。 |
| 计算与存储 | 1 台目标 Mac mini、持续写入能力合适的 SSD、1 台观赛浏览器 | 记录芯片、内存、系统版本、模型版本、码流、网络和空盘时长。按技术方案的容量公式制定留存期。 |
| 标定与真值 | 标定板、测量工具、已知高度的标杆、可见闪光或时间码装置 | 已测量但不参与拟合的检查点清单，独立参考相机或已测轨迹，设备与场地坐标示意图。 |
| 人员与样本 | 获准采集的球员、双方名单、可读和难读号码、授权范围 | 覆盖长传、禁区遮挡、带球绕人、交叉跑位、近身铲球及替补入场；安排逆光或晚场样本。 |

询价按镜头、触发、主机接口、安装、网络、存储和标注人工分别列项。先借用或试装一组设备测远场，再确定其余机位规格。预算金额由选定配置、供应商报价和场地布线长度计算。

## 3. 按周实施与放行条件

| 阶段 | 负责人／依赖 | 实际交付物 | 放行条件与失败处理 |
| --- | --- | --- | --- |
| W1–2　场勘与可行性 | A 主责，B、场务参与；需进场及样机 | 布点与覆盖图，近／远端像素样本，共同时码测试，单台 Mac mini 的解码和模型基准，首版验收集设计。C 固化现有演示的回归输入。 | **G1**　两处支架对同一次传球提供有效观测；远端球与号码有人工可辨样本；可核验曝光时刻。失败时先改位、焦距或触发方式并复测，再决定试点场地范围。 |
| W3–4　采集、标定、录像重放 | A、B；依赖 G1。C 并行做比赛模型和 v2 契约 | 八路采集器、分段索引、时钟映射、标定版本管理、录像输入驱动、空场／失球／未知号码契约样例。 | **G2**　八路连续录制 30 分钟；共同闪光和预留检查点达到 R02、R03 的试点门槛。拔一路明确告警，恢复后重新对时。异常机位隔离并复标。 |
| W5–6　人球闭环 | B 主责，A 提供输入，C 完成 v2 发布与基本观看；依赖 G2 | 人球检测基线、跨镜头 ID、球心与失球状态、在浏览器呈现真实训练片段、原片索引与叠加检查工具。 | **G3**　来自实拍的地面传球和高球都能在二维原片与三维画面对照。提交近／远端覆盖率、误差和 ID 切换明细。低置信样本可追到原因，未达标的区域回到取景或匹配调整。 |
| W7–8　骨骼、号码、动作复核 | B 负责估计，C 负责 UI，A 负责原片分发；依赖稳定轨迹 | 球衣多帧识别、名单绑定与人工纠正、至少两种模型、骨骼重定向、五类事件、逐帧与同步原片复核界面。 | **G4**　抽查遮挡、同号跨队、脚部接触次序和号码修订；复核人员可独立完成找事件、看原片、修订结果。记录每类 F1 和不足样本，未确认的事件保留候选。 |
| W9–10　八路性能与首场预演 | A 负责压测，B 调推理频率，C 完成监控、角色权限和恢复；依赖 G3、G4 | 目标机参数表、分环节耗时、资源曲线、降级策略、告警与恢复手册、一次全流程预演。 | **G5**　按约定人数连续 90 分钟回放或预演，统计所有预期时隙；完成断路、磁盘不足、服务重启、网络中断演练。软件回放成绩单独记录。 |
| W11　独立现场试点 | A、B、C 与场务、复核员；需 G5 | 一场目标场地实拍比赛、独立延迟对照、受控保存的录像和标注、问题清单、P0 签收记录。 | **G6**　按需求表逐项评定 R01–R11，区分通过、未通过及样本不足。出现重复 ID、长期丢球或延迟超过门槛时标注时段并修复，再用另一段实拍复验。 |
| W12　复盘、归档与发布 | C 主责，A、B 复测；需 G6 结果 | 可重复安装的版本、硬件配置、现场操作手册、按人／事件检索和导出、归档复算报告、发布说明。 | **G7**　R12 归档重放与导出通过；P0 未通过项逐项关闭或由项目方签署缩小试点范围的决定。发布说明写明实测机型、人数、场地和照明。 |

## 4. 验收分工与样本口径

| 验收对象 | 对应需求 | 主验收人 | 必须归档的证据 |
| --- | --- | --- | --- |
| 八路输入、时间和场地尺度 | R01、R02、R03 | 场务与 A，B 独立检查几何 | 配置、录像、共同闪光序列、独立空间检查点误差。 |
| 人球位置与身份 | R04、R05 | B 与标注人员 | 全部分母、覆盖率、近／远端误差、身份切换、读号混淆和人工修订。 |
| 动作与复核 | R06、R07 | B 与教练／裁判 | 标注约定、关节检查、事件类别明细、证据机位、缺证案例。 |
| 显示、端到端延迟 | R08、R09 | C 与 A | 暂停切机位对照、时钟误差、目标设备上的延迟分布、超期和掉帧时隙。 |
| 归档、权限、检索导出 | R10、R11、R12 | C 与场务 | 同步跳转清单、权限矩阵、恢复演练、删除结果、可复算导出样例。 |

1. **分样本。** 工程调试、阈值选择和最终验收按场次隔离。起步准备两次脚本化训练及至少一场独立比赛。五类动作各争取 30 个独立正例，并保留无动作时段和易混淆负例。稀有动作可组织安全演练；演练结果与自然比赛分别列报。样本不足的类别标记待验。
2. **建真值。** 两名标注人员在实拍原片上标出球员、号、球、可见性和事件区间。位置与骨骼误差用独立参考装置或人工标注的已标定独立视角求值，记录参考误差。无法获得可信三维真值的片段只评二维重投影与覆盖，不计入三维精度通过项。
3. **算指标。** 可见目标覆盖率分母取人工可见目标时隙；球员 ID 切换按被跟踪球员的总在场时间归一化。姿态误差采用球场坐标，报告样本量和参考误差。事件用同类、同参与者且起始时间相差不超过 1 秒的一对一匹配；带球等持续事件另报区间重叠率。定义在 G1 冻结，变更需同时重算基线。
4. **测时延。** 以冻结的发布频率生成预期时隙；计入过载、超期、缺失和断流。正常和人为故障时段分别统计，报告整体结果。第 11 周用同屏高帧率记录或可追溯时间码，独立验证曝光到浏览器首次绘制的端到端时间。
5. **归档清单。** 每次验收产生一次运行编号、Git 提交、模型和标定版本、场地与硬件信息、样本划分、指标、失败片段索引和复核结论。原始比赛资料按授权范围留在试点存储；仓库发布可共享的测试样例、说明和汇总指标。

## 5. 风险、触发条件与处理责任

| 观察到的风险 | 何时介入 | 处理与复测 |
| --- | --- | --- |
| 远端丢球、读不清号码 | G1 像素测量或人工判读失败 | A、B 重选角度和焦距，近端特写与远端覆盖协调；重走远端禁区和边线。覆盖缩水须更新承诺的场地范围。 |
| 八路曝光漂移或支架移动 | 闪光不同步、重投影残差持续变大 | A 检查触发、网络和时钟映射；B 隔离异常机位并重新标定。复验快速长传与高点。 |
| 单台 Mac mini 热机后积压 | 连续负载下队列年龄持续增长，预计超 30 秒 | A、B 分段定位，先调度姿态／OCR、复用解码缓存，再优化模型。若仍不足，报告目标机的实测上限与替代配置，重新走 G5。 |
| 人员交叉导致串号，遮挡后“假球”继续飞 | G3/G4 身份或失球样本错误 | B 调整跨机位匹配和预测时限；C 在网页展示缺测，复测同一片段及独立比赛。 |
| 铲球接触被挡住 | 两个独立机位均看不清关键瞬间 | 复核员标记证据不足；保留事件和原片。B 单独统计此类覆盖，不将动画当作判罚依据。 |
| 原片存储不足、网络中断或临时断电 | 剩余录制时长低于剩余赛程或分段写入失败 | A、C 告警、保护已归档段，恢复后修复索引并标出时间缺口；演练时核对已提交片段校验值。 |

## 6. 第一个迭代的工作清单

- A 和场务测量场地，列出四个候选位置；取得相机说明、SDK、目标 Mac mini 配置与实际样片，完成一组双目的可记录曝光测试。
- B 设计已知距离和高度的球路，记录同一号码从近端走到远端的像素变化；用两处视角做首次三角化并给出误差明细。
- C 从现有演示提取一条合法 v1 帧做回归样例，定义带未知号码、丢球、时钟重置的 v2 样例，准备同一时刻的原片与三维对照页。
- 项目方与复核人员确定目标场地、人数、设备配置、名单字段来源、录像授权与留存、验收指标和试点日期。G1 评审交付覆盖图、第一段实拍结果和修订排期，即可决定是否进入八路开发。

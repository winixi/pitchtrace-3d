## 🔴 P0 级缺失（阻塞 G1–G2 现场验收）

### 1. 实时采集层

#### 1.1 MVS SDK（海康机器人）集成
**文档依据**: `docs/02-technical-design.md` 第 2.1 节  
**设备型号**: MV-CS050-10GC-PRO × 2（双机起步）

- ❌ **缺少 `MVCamera` Swift wrapper**
  - 需要调用 MVS SDK 读取图像、设备帧号和时间戳
  - 需要配置 1920×1080 ROI、Bayer RG 8、30 fps
  - 需要启用相机端图像压缩

- ❌ **缺少曝光中心时间映射**
  - 文档要求：确认时间戳对应曝光起点还是中心
  - 若为起点，需加上曝光时长的一半
  - 映射为 UTC 后写入 fMP4 索引

- ❌ **缺少 VideoToolbox 编码链路**
  - 文档要求：MVS 直采 → Mac 硬件编码 → fMP4
  - 当前 `replay` 仅处理已有 H.264 文件

**阻塞**: W3（单台录像与重连）、W4（四路连续 30 分钟）

---

#### 1.2 PTP 对时验证
**文档依据**: `docs/02-technical-design.md` 第 2.1 节  
**验收标准**: P95 ≤ 5 ms

- ❌ **缺少读取 GigE Vision 设备 PTP 锁定状态**
  - 需要查询 PTP 时钟同步状态寄存器
  - 记录时钟漂移与重锁定事件

- ❌ **缺少定时触发曝光配置**
  - 若固件支持，配置按指定 UTC 触发
  - 若不支持，需测试 Line 0 外触发源

- ❌ **缺少共同闪光复核工具**
  - 文档要求：用各机位可见的同步闪光复测
  - 需要在图像传输期间实时计算曝光中心时刻差

**阻塞**: G1（双机位对时报告）、G2（四路曝光偏差统计）

### 2. 视觉推理层

#### 2.1 Core ML 模型加载与推理
**文档依据**: `docs/02-technical-design.md` 第 3 节  
**当前状态**: `VisionObservation.swift` 仅 94 行占位实现

- ❌ **缺少 Core ML 模型文件加载**
  ```swift
  // 需要实现：
  let model = try MLModel(contentsOf: modelURL)
  let visionModel = try VNCoreMLModel(for: model)
  ```

- ❌ **缺少 `CVPixelBuffer` 预处理管道**
  - 需要调整分辨率（如 640×640）
  - 需要归一化像素值（0–255 → 0–1 或其他范围）

- ❌ **缺少人框/球框置信度过滤与 NMS**
  - 需要解析 YOLO 输出（边界框 + 类别 + 置信度）
  - 需要应用 Non-Maximum Suppression 去重

- ❌ **缺少小球精搜（ball-search）实现**
  - 文档要求：全图检测 + 原图裁片精搜
  - 丢球时扩大搜索范围
  - 需要保留周期性全图搜索

**阻塞**: G3（实拍轨迹精度验证）、G5（整场吞吐测试）

---

#### 2.2 Vision 姿态与 OCR
**文档依据**: `docs/02-technical-design.md` 第 4 节

- ❌ **缺少 `VNDetectHumanBodyPoseRequest` 调用**
  - 需要从人框裁片提取 2D 关键点
  - 需要记录每个关节的置信度
  - 需要按轨迹与曝光时刻归档

- ❌ **缺少 `VNRecognizeTextRequest` 号码识别**
  - 需要从背号裁片读取文字
  - 需要实现多帧投票逻辑
  - 号码稳定后降低该轨迹的读号频率

**阻塞**: G4（读号正确率与覆盖率）、G6（姿态覆盖率验收）

---

#### 2.3 观测质量评估
**文档依据**: `docs/02-technical-design.md` 第 3 节

- ❌ **缺少模糊度与遮挡比例计算**
  - `observation_quality.py` 仅 61 行
  - 需要接入模糊度检测（Laplacian 方差或其他）
  - 需要估计遮挡比例（边界框完整性）

**阻塞**: G3（观测质量筛选）、G6（证据不足样本统计）

## 🟡 P1 级缺失（阻塞 G3–G6 功能完整性）

### 3. 三维融合层

#### 3.1 跨视角关联
**当前状态**: `tracking.py`（370 行）实现了 Python 原型

- ⚠️ **缺少 Swift 或 C++ 生产实现**
  - 需要时间、极线距离、地面位置筛选
  - 需要队服、号码、外观特征构造代价矩阵
  - 需要匈牙利算法匹配观测

- ⚠️ **缺少重投影误差剔除**
  - 需要计算多视角三角化后的重投影残差
  - 需要动态剔除异常机位

**阻塞**: G3（轨迹 ID 稳定性）、G4（ID 切换次数验收）

---

#### 3.2 三角化与重投影
**当前状态**: `camera_geometry.py` 存在基础函数

- ⚠️ **缺少多视角射线三角化的鲁棒实现**
  - 需要检查交会角（文档要求 ≥1°）
  - 需要加权最小二乘或 RANSAC
  - 单视角时需标记三维缺测

- ⚠️ **缺少夹角检查与质量评分**
  - 需要记录观测数量、夹角、重投影误差
  - 需要区分地面投影与空中三角化

**阻塞**: G3（球心三维误差 P95 ≤1.0 m）、G6（关节平均误差 ≤0.20 m）

---

#### 3.3 卡尔曼滤波与短时预测
**文档依据**: `docs/02-technical-design.md` 第 3 节  
**要求**: 0.3 秒预测有效期

- ❌ **缺少状态估计器实现**
  - 需要位置、速度、加速度状态向量
  - 需要协方差传播与测量更新
  - 预测超期后转为 `state: lost`

**阻塞**: G3（球员覆盖率 ≥95%）、G4（可见球覆盖率 ≥85%）

---

### 4. 身份与动作层

#### 4.1 球队与号码识别
**当前状态**: `analysis.md` 描述了逻辑，但代码缺失

- ⚠️ **缺少队服颜色提取**
  - `detector.teamColors` 配置已存在（映射球队 ID → sRGB）
  - 需要从人框裁片提取主色调
  - 色差大或两队难以区分时保留球队未知

- ⚠️ **缺少 OCR 多帧投票实现**
  - 需要清晰裁片做文字识别
  - 需要连续多帧投票稳定号码
  - 冲突或置信度不足时保留候选

- ⚠️ **缺少名单 ID 绑定逻辑**
  - 需要同队唯一匹配或人工确认
  - 轨迹 ID、名单 ID、号码分别存储
  - 修号后历史轨迹沿用原轨迹 ID

**阻塞**: G4（自动确认号码正确率 ≥95%、覆盖率 ≥70%）

---

#### 4.2 骨骼融合与重定向
**当前状态**: `pose.py`（142 行）仅做二维估计

- ⚠️ **缺少多视角关节融合**
  - 需要按同一轨迹、同一曝光组帧
  - 需要三角化髋、膝、踝等关节
  - 需要约束骨长与关节活动范围

- ⚠️ **缺少局部四元数计算**
  - 需要按绑定姿态和父骨骼坐标重定向
  - 需要映射到基础模型（前端 13 关节）
  - 需要保存原始测量与平滑结果

**阻塞**: G4（关节覆盖率建议 ≥80%）、G6（关节平均误差 ≤0.20 m）

---

#### 4.3 五类事件候选生成
**当前状态**: `match_events.py`（285 行）存在规则框架

- ⚠️ **缺少摆腿检测与球加速对齐**
  - 需要提取脚部位置与摆动时段
  - 需要估计出球位置、球速变化与方向
  - 射门需检查方向是否支持

- ⚠️ **缺少传球、带球、过人、铲球的完整实现**
  - 传球：控球者脚附近球加速离开 + 队友接球
  - 带球：球多次随同一球员推进
  - 过人：与防守者相对位置变化后仍控球
  - 铲球：重心下降 + 腿伸展 + 距离骤减

- ⚠️ **缺少证据帧引用与人工修订接口**
  - 需要关联原片时窗
  - 需要记录置信度与参与者
  - 需要支持人工更改标签

**阻塞**: G4（逐类精确率、召回率，宏平均 F1 ≥0.75）

### 5. 持久化与上行层

#### 5.1 断网重连与限速补传
**当前状态**: `MediaPublishing.swift` 仅实现一次性上传（200 行）

- ❌ **缺少优先级队列**
  - 文档要求：当前帧优先，再按带宽补历史
  - 需要持久化待办队列（SQLite 或文件）
  - 需要记录每段的提交状态

- ❌ **缺少断点续传逻辑**
  - 409 冲突后的幂等重试已有
  - 但队列持久化缺失，重启后丢失待办

- ❌ **缺少限速控制**
  - `--backfill-bytes-per-second` 仅在 `publish-scenes` 存在
  - 原片上传需要独立限速（建议 10 秒窗口均值 ≤0.8 Mbps）

**阻塞**: G5（故障预演与恢复测试）、G6（断网继续录制验收）

#### 5.2 恢复与待办扫描

  - 需要重新提交缺失的初始化文件、片段或索引

**阻塞**: G5（重启恢复验收）、G6（提交回执与缺口记录）

#### 5.3 场景归档事务（Swift 侧）

  - 若需要 Swift 实时写入，需要实现 SQLite wrapper
  - 或继续使用 Python 子进程（当前方案）

**阻塞**: 若采用纯 Swift 实现，需补充此模块

## 🎯 推荐开发顺序（按 W1–W12 计划）

### W3–W4（G1–G2 准备）
1. **MVS SDK 集成** - 单台录像、重连、四路连续 30 分钟
2. **PTP 对时验证** - 共同闪光复核，P95 ≤ 5 ms
3. **Web UI 通道预览** - 实时查看各机位画面

### W5–W6（G3 准备）
4. **Core ML 推理循环** - 人球检测基线
5. **小球精搜** - 原图裁片二次检测
6. **跨视角关联** - 轨迹 ID 稳定性
7. **三角化与重投影** - 球心三维误差

### W7–W8（G4 准备）
8. **Vision 姿态** - 2D 关节提取
9. **Vision OCR** - 号码识别与多帧投票
10. **骨骼融合** - 多视角关节三角化
11. **事件候选** - 摆腿检测与球加速对齐

### W9–W10（G5 准备）
12. **队列持久化** - 断网重连与待办扫描
13. **限速补传** - 当前帧优先 + 带宽控制
14. **标定版本切换** - 按曝光自动隔离与恢复

### W11–W12（G6–G7 准备）
15. **权限管理** - 设备认证与角色分离
16. **HLS 播放列表** - `.m3u8` 生成与曝光定位
17. **比赛创建接口** - Live 侧生命周期管理
